Every support call

Three questions, on every machine.

01What is slow?
02Why?
03Is it safe to clean up?

Existing tools answer one each. None of them show their work — and a tool that guesses a cause is worse than one that says nothing.

Slow down on the third question: it is the one that makes the cleaner part of the story rather than a bolt-on. "These three are the same question at different depths: what is happening, why, and what will break if I touch it."

One window, two directions

The phone tells the PC what it has. The PC tells you what is wrong with it.

No account. No telemetry. Standard-user APIs only — the collectors never ask for administrator rights.

Do not read the bullets. Point at two per column: "replies from the PC" and "commit charge" — the second is the one that answers 'it says out of memory and there is plenty of RAM'.

The decision that shaped everything

A missing number is not a zero. It carries why it is missing.

Memory — waiting for the second sample
what a naive tool draws 0 % "idle" — while the read had failed

MetricState is a value, or the reason there isn't one. The snapshot publishes nothing for a metric it does not have — so a rule cannot cite it, and the tile cannot draw it as zero.

Slow, quiet delivery. This is the sentence the judges will repeat: "a missing measurement is not a zero." If you only win one slide, win this one.

If asked why only ten: "ten rules that each ship with a firing case and a near-miss, versus a hundred that fire on every machine." Point out the CPU pair as one decision written twice.

The expensive half of a rule

A rule that cannot be made silent is a rule that fires on healthy machines.

89.9 % for twelve minutes

One tenth under the line, held well past the window. Quiet.

the same pid, a new process

Windows reuses pids. The rule keys on the creation stamp, so a recycled pid is a different subject. Quiet.

0.000 s per transfer

An idle disk is not an infinitely fast one, and not a slow one. Zero is a reading, never a finding. Quiet.

3 min on · 1 min off · 3 min on

A program starting and settling, not a machine out of memory. The window is broken, so the claim fails. Quiet.

28 fixtures — a machine behaviour and its expected findings, compared as an exact set: a new rule that fires on an old fixture breaks the build.

This slide is what separates the project from a dashboard. Each example is a real fixture file in the repository; name one path if a judge asks.

How it is built

Boundaries that are compile-time facts, not good intentions.

desktop/app Qt 6 / QML, 13 pages, cxx-qt bridge may not be referenced by any core crate
sa6i-link-intel-win Windows collectors: PDH, Win32, NT may not depend on core
sa6i-link-intel model · 10 rules · store · findings · TOML loader may not touch an OS API, Qt, or a socket
sa6i-link-core link · pairing · transfer · mirroring · protocol may not know diagnostics exist
sa6i-link-cli snapshot · JSON · history — the headless proof may not need Qt

Diagnosis must not require a phone, a pairing or a transport — so "does it work without the app on the other side?" is answered by the compiler, not by a test run.

If a judge asks why not Qt everywhere or Rust everywhere: the shell is where native windows, a virtual camera and a Win32 host meet; the core is where measurement must not be interrupted by a runtime.

Privacy, as a test rather than a promise

The network stack is not unreachable by policy. It is not in the dependency graph.

cargo test -p sa6i-link-intel

reads Cargo.lock, builds the graph by crate name, and fails if either intel crate can reach anything socket-capable.

intel closure62crates · socket-free
intel-win closure74crates · socket-free

The list of crates allowed to open a socket is a ratchet in a test: adding one is a visible, deliberate edit to a file a reviewer can read.

Say "the test reads the lock file" rather than "we don't use the network". The distinction is the whole slide.

The bug worth showing

A deletion path the upstream guard did not cover — found by not trusting it.

$ node sa6i/clean/tests/probe_upstream_cleanup.mjs
linkTargetRefused                     true   // a junction target is refused
redirectedRootAcceptedAsRealDirectory true   // a junction ABOVE the root looks ordinary
deletedThroughRedirectedAncestor      true   // and deletion follows it

upstream  followed a junction above a cache root on real NTFS.

ours  refuses it, and still cleans ordinary folders — including 8.3 and differently-cased spellings.

always  Windows, Desktop and .ssh are refused as targets.

This is your strongest technical story: plausible guard, real blind spot, a probe that proved it on real NTFS with synthetic files and sentinels, and a fix verified the same way. Say that no real cleanup has been run in the same breath.

The hosting problem

One window. The cleaner is a child, not a second application.

1 · pin it

The host verifies the exact hash of the cleaner's executable and ASAR before launching, so the wrong build cannot be hosted by accident.

2 · clip it

The child is reparented into a same-process clipping container sized to the Qt viewport — it cannot paint or take input outside it.

3 · order the exit

Hide the container, then the asynchronous child hide, then reap the process before the container is destroyed.

A separate --restricted build blocks twelve IPC routes, including cleanup and uninstall, and the host verifies that exact binary. It is not a sandbox, and the documentation says so in those words.

Know the failure that started this: the cleaner covered the Back header. The 40-pixel clearance is a workaround and the underlying compositor offset is still unexplained — say that if asked rather than inventing a cause.

Backup · short answers

The five that are asked hardest, in one line each.

"Isn't this KDE Connect?" Same lane, plus a diagnosis none of them do — and the diagnosis is the half nobody else is in.
"Have you checked the numbers?" No. Same PDH counters Task Manager reads; one command and one PC close it.
"You didn't write the cleaner." Correct — and that's why the provenance work and the guard exist.
